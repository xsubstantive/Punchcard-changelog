## CoAudit and Punchcard

- **Set up Punchcard triggers by asking CoAudit.** From any page, ask CoAudit to list, create, update, pause, resume, run or delete a trigger. A trigger is a saved set of instructions that Punchcard runs on its own for an engagement. It can start when a Request is submitted, accepted or returned, when it receives documents or comments, on a weekly schedule, at a set time, or only when you run it.
- **Hand internal tasks to Punchcard.** Ask CoAudit to have Punchcard work on a task right away, or to start when the task is accepted. If the task is related to Requests, Punchcard starts once all of them are accepted. You can also take a task back from Punchcard.
- **Link Requests and tasks.** Ask CoAudit to show, add or remove the Requests and tasks that are related to each other. The change appears on both sides.
- **Name items the way you see them.** Refer to a task by the short ID shown on screen, such as "AUDI-12", or describe it in words.
- **You stay in control.** CoAudit asks for your approval before every change. The approval card says what will happen and which items it affects, including whether results will be visible to the client.

## Improvements

- **Related items and trigger lists refresh right after CoAudit changes them**, so a later edit you make by hand doesn't undo CoAudit's change.
- **Filters based on Request details**, such as assignee, category or status, are still set on the engagement's Triggers tab.

## Fixes

- **Sub-request folders keep the order in which they were created.**
